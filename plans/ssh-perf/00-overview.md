# 00 — 总览

## 一句话

把 SSH 扫描从"卡死要重启"改造成"500ms 内见缓存、3-10s 内完成新扫描、可取消可观察"。

## 量化目标

| 指标                              | 现状（推算）  | 目标          |
|-----------------------------------|---------------|---------------|
| 首屏可见时间（看到上次缓存）      | 不确定/卡住   | ≤ 500ms       |
| 完整 SSH 扫描时间（30 agent）     | 60-200s       | ≤ 10s         |
| SSH spawn 进程数 / 次扫描         | 100-200       | 1（持久会话） |
| 单次握手代价                      | 0.5-2s        | ≤ 50ms（复用）|
| 切 target 后右栏刷新延迟          | 不刷          | ≤ 200ms       |
| 不可达 host 卡住时长              | 永久          | ≤ 90s 终止    |
| scan_state 残留导致首屏卡 Loading | 偶发          | 0（启动自愈） |

## 总体策略

```text
[阶段 1] ── 稳定性兜底 ──┬── 超时
                        ├── scan_state 自愈
                        └── 切 target 联动 rescan
                          目的：先让"卡住"消失

[阶段 2] ── 批量化 ──────┬── run_remote_script
                        ├── 一次 find 找全部 SKILL.md
                        └── 一次批读全部 SKILL.md 内容
                          目的：单次扫描 SSH 调用 N → 1

[阶段 3] ── 换 russh ────┬── ConnectedSshTarget 改持久 session
                        ├── 同 target 复用 client
                        └── 删掉 ssh.exe 子进程路径
                          目的：握手只一次，跨命令复用

[阶段 4] ── UX ──────────┬── 缓存先显示
                        ├── 进度阶段 emit 事件
                        └── 取消按钮 + CancellationToken
                          目的：可见可控

[阶段 5] ── 边角 ────────┬── bootstrap SQL 并发
                        └── exists+read 合并
                          目的：扫尾
```

## 阶段间依赖

```text
阶段 1（不破坏现状的最小防御层）
  └─ 可独立合并、立即上线
     │
阶段 2（批量化，依赖阶段 1 的超时与 cancel）
  └─ 可独立合并
     │
阶段 3（换 russh，要重写 ConnectedSshTarget）
  └─ 大改，需保留 fallback：检测 russh 不可用时退回 ssh.exe？否
     直接切，旧实现删掉
     │
阶段 4（UX，依赖阶段 1 的 CancellationToken 和阶段 2 的 emit hook）
  └─ 可与阶段 3 并行
     │
阶段 5（边角，可任何时候做）
```

## PR 拆分建议

| PR  | 范围                  | 估时    | 风险 |
|-----|-----------------------|---------|------|
| PR1 | 阶段 1 全部           | 1-2 天  | 低   |
| PR2 | 阶段 2 全部           | 2-3 天  | 中   |
| PR3 | 阶段 3 全部（russh）  | 3-5 天  | 高   |
| PR4 | 阶段 4 全部           | 1-2 天  | 中   |
| PR5 | 阶段 5（可选打包）    | 0.5 天  | 低   |

总估时：约 8-13 天工作日，不含 review 与回归。

## 验收门槛（阶段 5 完成后整体）

- 真实 dckj 远端首屏可见缓存 ≤ 500ms
- 30 agent 完整扫描端到端 ≤ 10s（家宽，不计 cold cache）
- 关闭网络后 90s 内 UI 显式 error
- 切 target 后 200ms 内右栏新数据
- `cargo test` + `pnpm test` + `cargo clippy -- -D warnings` 全绿
- 手工：在 dckj 跑 100 次连续扫描，无残留 scan_state、无 askpass 临时文件残留
