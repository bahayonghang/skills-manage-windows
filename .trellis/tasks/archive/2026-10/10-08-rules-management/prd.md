# Rules 管理与 Claude Code、OMP 软链接分发

## 目标

在 SkillPort 左侧增加 Rules 管理入口。用户在一个页面管理规则正文，并分别控制 Claude Code 与 Oh My Pi（OMP）是否读取每条规则。初始内容来自当前 `~/.claude/rules`，中央规则库位于 `~/.skillport/rules`，两个目标工具通过文件 symlink 读取中央文件。

## 授权与状态

- 用户已要求创建任务与设计前后端，随后确认首版目标为「claude，omp」。
- 用户在后续消息明确授权「开始实施」，任务进入 `in_progress`。
- 实施与测试使用隔离目录；真实用户目录初始化和链接接管由新界面内操作触发。

## 已确认事实

- 2026-10-08 本机 `~/.claude/rules` 为普通目录，含 6 个平铺 UTF-8 Markdown 文件，无 BOM、无 YAML 头部，采用 LF。
- 文件为 `anti-patterns.md`、`chinese.md`、`clarity.md`、`durable-context.md`、`english.md`、`waza-routing.md`。
- `~/.omp/agent/rules` 含 6 个同名普通文件，均有 `alwaysApply: true` 和 `description`。去除 OMP 头部和首尾空白后，6 组正文相同；完整文件字节不同。
- `omp --version` 为 `omp/18.8.6`；相关目录覆盖变量在当前进程未设置。
- 仓库在 `dev` 分支，创建任务前工作区干净。现有技能、数据库仍使用 `~/.skillsmanage`，新功能不迁移这些数据，见 `src-tauri/src/paths.rs:14`。
- 当前 Tauri 窗口为 1200×800，最小为 900×600，见 `src-tauri/tauri.conf.json:18`。

来源与接口限制见 [research/current-state.md](research/current-state.md)。

## 风险与前置条件

- 规划时 `just doctor` 失败：pnpm 为 `12.10.1`，当时仓库要求 `10.34.5`；其他探测项通过，规划阶段未修改安装或 PATH。
- 用户后续授权「使用最新版本的pnpm」「删除仓库的声明版本，优先使用最新版」。实施移除 pnpm 精确版本声明，使用现有最新稳定版 `12.10.1`，doctor 与 CI/doc 配置同步；Node 26 和 Rust 1.98.0 保留。
- 规划时 Windows 开发者模式注册表值为 1，仅为配置证据。实施后在隔离 home 创建并回读真实文件链接，证据见 [validation/results.md](validation/results.md)。
- OMP 官方 main 文档/源码支持规则元数据设计，本机版本的链接发现需隔离运行验收。若发现失败则返回规划，不使用复制降级。
- 规则更新要由工具重新加载；界面不承诺当前会话即时更新。
