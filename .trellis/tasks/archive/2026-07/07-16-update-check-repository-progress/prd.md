# 更新检查仓库进度反馈

## Goal

当用户从“选择更新检查模式”弹窗启动检查时，提供真实、可感知的仓库级进度，明确已完成仓库数以及当前正在处理的 GitHub 仓库，避免长时间只显示“检查中...”而无法判断是否仍在工作。

## Confirmed Facts

- 当前交互由 `UpdateCheckModeDialog` 发起；提交后模式卡片和取消按钮被禁用，确认按钮仅显示“检查中...”，直到 `useUpdateCenterStore.refresh(scope)` 一次性返回。
- 前端 `updateCenterStore` 只有 `isRefreshing` 布尔状态，没有总仓库数、已完成数或当前仓库信息。
- 后端 `refresh_skill_update_inventory` 会把技能来源仓库和显式仓库范围合并、去重后下载 GitHub 快照；常规模式也可能涉及多个仓库。
- 仓库快照下载通过 4 路并发执行。进度设计不得为了显示单一仓库而改成串行并造成性能回退。
- 仓库有稳定的 `owner/repo` 显示信息；用户可见文案必须同步维护中英文 i18n。
- 现有 Central 更新应用流程已有 Tauri progress event、前端监听和 Zustand 合并状态的实现模式，但库存刷新目前没有仓库级事件。
- 刷新失败必须继续遵守现有契约：弹窗保持打开、显示内联错误和 toast，并允许重试。

## Requirements

- R1. 确认检查后，模式弹窗保持打开并显示进度条；短暂准备阶段允许无确定值，进入仓库处理阶段后必须显示 determinate 进度。进度值来自后端实际仓库处理事件，不使用定时器或估算动画伪造百分比。
- R2. 进度区域显示 `已完成仓库数 / 总仓库数`，并列出全部当前活跃仓库的 `owner/repo` 名称；不得展示凭据、完整本地路径或不必要的 URL。
- R3. 后端必须在去重后的实际仓库集合确定后报告总数，并在每个仓库开始及完成时报告状态；缓存命中若进入该路径，也必须计入完成数。
- R4. 保留当前最多 4 路仓库快照下载并发，不为获得线性进度而串行化网络请求。
- R5. 进度事件只服务本次 Update Center 库存刷新，不得污染现有 `central://skill-update-progress` 的按技能应用/检查语义。
- R6. 前端 store 负责订阅、合并和清理刷新进度状态；组件只消费 store/controller 状态，不直接调用 Tauri IPC 或事件 API。
- R7. 订阅必须在调用刷新命令前建立，并在成功、失败和组件/动作结束时可靠解除，避免丢失首个事件或残留监听器。
- R8. 成功后保持当前行为：关闭模式弹窗，按 inventory 首选 tab 打开更新中心，并清空临时进度状态。
- R9. 失败后保持当前行为：模式弹窗不关闭，显示内联错误和 toast，提交按钮恢复可用；下一次重试从零开始，不能显示上一次仓库或百分比。
- R10. 所有新增可见文本和无障碍名称必须同时提供英文、简体中文翻译；进度条使用 `role="progressbar"` 及正确的 `aria-valuemin`、`aria-valuemax`、`aria-valuenow`。
- R11. 无可检查 GitHub 仓库或尚未收到总数的短暂阶段必须有稳定、不跳布局的状态，且不能出现 `NaN`、除零或错误的 100%。
- R12. 用户确认后，弹窗主体从模式选择卡片切换为专注的进度视图，不继续展示不可操作的模式卡片和警告；检查失败时恢复模式选择，并保留现有内联错误、toast 和重试能力。

## Acceptance Criteria

- [x] AC1. 启动跨多个仓库的检查后，弹窗展示仓库级进度条、已完成/总数，以及全部当前活跃仓库的 `owner/repo` 名称；仓库完成后从活跃列表移除。
- [x] AC2. 后端测试证明进度总数基于去重仓库集合，开始/完成事件与真实下载生命周期一致，完成数单调递增且最终等于总数。
- [x] AC3. 并发检查保持现有最多 4 路下载能力；实现和测试不依赖固定完成顺序。
- [x] AC4. 前端 store 测试覆盖订阅先于 invoke、事件合并、成功清理、失败清理和重试重置。
- [x] AC5. 弹窗组件测试覆盖 0/未知总数、1 至 4 个并发活跃仓库、完成前一刻、长仓库名、错误与无障碍属性。
- [x] AC6. controller/view 测试证明成功仍打开正确的 Update Center tab，失败仍显示内联错误和 toast，且两条路径均不泄漏事件监听。
- [x] AC7. 中英文界面均无缺失翻译，长 `owner/repo` 名称在窄弹窗内截断但可通过原生 title 或等价可访问名称读取完整值。
- [x] AC8. 定向前端 Vitest、相关 Rust 单元测试、`pnpm typecheck`、`pnpm lint`、`cargo clippy -- -D warnings` 和最终 `just ci` 全部通过。
- [x] AC9. 提交检查后模式卡片和警告由进度视图替换；若刷新失败，模式卡片重新出现，原选择保持不变，用户可直接重试。

## Out Of Scope

- 为更新检查增加取消/中断能力。
- 改变常规检查与增量删除模式的范围语义。
- 改变 Update Center 中导入、删除、强制更新或应用更新的确认流程。
- 将仓库下载改为串行，或重新设计 GitHub 快照缓存与网络重试策略。
- 为非 GitHub、本地未知来源或平台冗余扫描虚构仓库级进度。
