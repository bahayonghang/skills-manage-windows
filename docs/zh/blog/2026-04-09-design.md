# 桌面设计

> **日期：** 2026-04-09 · **状态：** historical · **来源：** `docs/desktop-design.md`

桌面布局围绕五个主屏面设计，每个都回答一个用户带进来的问题。

## 五屏面

```text
┌──────────────────┬──────────────────────────────────────────────┐
│ 页面             │ 回答的问题                                   │
├──────────────────┼──────────────────────────────────────────────┤
│ Central Skills   │ "我有哪些技能？"                              │
│ Platform View    │ "这个 agent 装了什么？"                       │
│ Skill Detail     │ "这个技能到底做什么？"                        │
│ Collections      │ "我想批量管理一组技能。"                      │
│ Discover         │ "项目里散落了哪些 SKILL.md？"                  │
└──────────────────┴──────────────────────────────────────────────┘
```

设计起点是 "Central 即真相源"，其他屏面都是 Central 的视图。这条主轴推出三个下游决策：

1. **优先 symlink。** Central 技能透过 link 传播到平台，避免重复持有。
2. **导入即集中化。** 进入 SkillPort 的所有内容先落到 Central，再走平台安装。
3. **没有屏面直接编辑平台目录。** 编辑都走 Central。

## 页面映射

| 页面 | 路由 | 布局 |
| --- | --- | --- |
| Central Skills | `/central` | 双列技能卡片 |
| Platform | `/platform/:agentId` | 双列技能卡片，按 agent 过滤 |
| Skill Detail | `/skill/:skillId` | Markdown + 含安装状态/集合的 sidebar |
| Collections | `/collections` | 上方选中卡 + 下方成员列表 |
| Discover | `/discover[/:projectPath]` | 项目列表 + 项目技能详情 |

## 为什么用侧栏，不用 Tab

五个屏面在 1280 宽度的横向 Tab 上太挤。垂直侧栏在 960px 以下折叠为图标，命令面板（`Ctrl+K`）作为键盘加速器。
