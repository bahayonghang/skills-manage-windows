# 技能协议调研

> **日期：** 2026-04-09 · **状态：** historical · **来源：** `docs/research-report.md`

在确定 SkillPort 的技能格式之前，调研了已有 AI agent 生态对 "技能" 的描述方式。下列结论至今驱动当前协议。

## 上游已有的 "技能"

| 来源 | 形态 |
| --- | --- |
| [Anthropic Agent Skills](https://github.com/anthropics/agent-skills) | 目录 + 带 frontmatter 的 `SKILL.md` |
| Claude Code marketplace 插件 | 插件清单指向一个或多个技能目录 |
| Codex CLI / Cursor / Gemini CLI | 共读 `~/.agents/skills/` |
| 自定义厂商 agent | 各自挑 `~/.<vendor>/skills/` 子目录 |

文件系统层面这些形态同构——都是带顶层 markdown 的目录。差异在：

- 目录放在哪。
- frontmatter 里携带什么元数据。
- 目录下的同级资源是否被 agent 识别。

## 采纳约定

SkillPort 完全采纳 Anthropic 的开放格式：

- `SKILL.md` 是入口文件。
- frontmatter 是 YAML，含 `name`、`description`，可选 `version` / `tags` / `author` / `homepage`。
- `reference/` / `scripts/` / `assets/` 等同级目录原样透传。

详细规范见[参考 → 技能协议](../reference/skill-protocol.md)。

## 被否决的方案

| 候选 | 否决原因 |
| --- | --- |
| 单文件 `.skill.md`（无目录） | 丢失真实技能依赖的同级资源 |
| TOML frontmatter | YAML 是已有约定，切换会破坏生态技能 |
| 必填 `version` | 大量社区技能不写，强制会破坏它们 |
| 同级 JSON manifest | 元数据出现两个真相源 |

## 存储决策

SkillPort 为每个技能持有三份视图：

```text
┌─────────────────────────┬─────────────────────────────────────────┐
│ 视图                    │ 来源                                    │
├─────────────────────────┼─────────────────────────────────────────┤
│ Central canonical       │ ~/.skillsmanage/skills/<id>/            │
│ Platform install        │ ~/.<platform>/skills/<id>/  (symlink)   │
│ DB row（skills 表）     │ frontmatter + canonical_path 的镜像     │
└─────────────────────────┴─────────────────────────────────────────┘
```

UI 绑定 DB 行。重扫时按磁盘真相对齐：DB 写 `description = "old"`，文件写新内容时，文件赢。

## 2026-04-09 的悬而未决

- AI 生成的标签写回目录还是只入库？**结论：** 只入库；SkillPort 不重写用户的 SKILL.md。
- 集合需要稳定的导出格式吗？**结论：** 需要，见[状态导入 / 导出](../reference/state-import-export.md)。
- 同一项目里多个 SKILL.md，Discover 是否优先取最新？**结论：** 列出全部，导入时由用户选择。

仓库内 `docs/research-report.md` 是完整调研笔记。
