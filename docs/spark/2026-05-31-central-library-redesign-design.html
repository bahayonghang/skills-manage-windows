中央技能库优化 · 设计规格

  • 日期：2026-05-31
  • 主题：中央技能库 UI 重排 / 卡片重设计
  • 范围：选择性吸收（仅前端）
  • 状态：待用户评审

摘要

以参考项目 skills-manager 的 Library 页面为参照，对本项目中央技能库（/central）做纯前端的视觉与信息架构优化，不改动任何后端、IPC、数据流或既有功能。三条主线：

  1. 信息架构重构：把当前混在一个 facet 侧栏里的 repo 与标签拆开——仓库（repo）上升为左侧主导航，标签与来源筛选下沉为顶部横向 pill 行。
  2. 头部 chrome 收敛：把现在的三层堆叠（标题按钮行 / 搜索行 / 常驻选择控制行）压成双行，删除常驻的"已选 0 · 共 N"行，选择控制上下文化。
  3. 卡片重设计（方案 C）：升级 UnifiedSkillCard——左侧状态竖条、状态 chip、彩色可增删标签、底部分隔线 footer（来源 repo · preset · 调用次数 ｜ 平台点 + 启用状态），网格改为自适应换列。

目标

  • 左侧栏成为仓库导航：列出"全部 + 各 repo"（色块头像 + 名称 + 数量 + 可更新提示）+「同步新源」入口；单选切换过滤。
  • 顶部新增筛选 pill 行：来源（全部 / Local / Git / skills.sh 等）+ 彩色标签 pills +「更多▾」（容纳 Tag Groups）。
  • 头部由 3 行压到 2 行；删除常驻选择行，选择摘要仅在有选中时内联到搜索行。
  • 卡片采用方案 C：竖条编码状态、状态 chip、AI 摘要 chip、彩色可增删标签、footer 分隔线、平台点（已链接 N）。
  • 卡片网格自适应换列（按最小列宽 2–4 列）。
  • 选「全部」默认平铺，并保留「按 repo 分区」视图开关（复用现有 groupByRepository）；选某 repo 仅显示该 repo 技能。
  • 标签配色：优先用 SkillTag.color，未设置则按标签名哈希到主题色板。
  • 全部新增/改动文案走 i18n（中英双语）；通过 pnpm typecheck / pnpm build / pnpm test。

非目标（本次明确不做）

  • 不改动 Rust 后端、任何 #[tauri::command] IPC、SQLite schema 或数据流。
  • 不改动既有功能逻辑：更新中心、任务中心、平台管理、AI 标签建议、批量安装/删除、状态导入导出、自动中央化（ensure_centralized）等一律保留。
  • 不重写已稳定的对话框 / 抽屉 / 进度渲染单元（dialogs / drawers / progress）。
  • 不引入新的卡片组件——继续只用 UnifiedSkillCard（项目既定约定）。
  • 不做"全面对齐参考密集风格"的大改（已在范围决策中排除）。
  • 不改动其他页面（平台视图、集合、项目、市场、设置）；本次仅限 /central。注：UnifiedSkillCard 为多页面共用，改动需保证其它场景（platform/project/marketplace/collection）视觉不回归——见风险。

背景

当前实现

  • Shell（src/components/central/CentralSkillsShell.tsx）：三层堆叠头部 = ①标题+路径+一排全文字按钮（GitHub导入 / 更新中心 / 检查更新 / 批量更新 / ⋯）②搜索 + 排序 + 视图 ③常驻选择控制行（CentralSelectionControls：已选 N · 共 M ｜ 全选当前 · 清空）。
  • 侧栏（CentralSidebar.tsx）：可调宽 facet 侧栏，repo 与标签混在一起，含 Saved Views、Tag Groups。
  • 卡片（src/components/skill/UnifiedSkillCard.tsx）：rounded-xl + ring-1，四行结构（名称+操作图标 / 描述 line-clamp / meta badges / 平台切换图标）；无 footer 分隔线、无状态竖条、标签不可在卡上增删。
  • 分组能力已存在但未突出：centralViewState.ts 的 GroupByMode = "none" | "repository" | "owner" | "tag" | "status"；centralGrouping.ts 的 groupByRepository() 已能按 skill.repository 切分。默认是 "none"（平铺），且开关藏在「视图▾」菜单里。
  • 数据模型已支持标签颜色：SkillTag（src/types/index.ts）已有可选 color 与 group_id 字段。
  • 卡片已有 comfortable / compact 两档密度（viewState.density），描述行数随之 3 行 / 2 行。

用户意图

用户提供参考图 ref/skills-manager/assets/demo/library.png，希望中央技能库在不损失现有功能的前提下，吸收参考的紧凑、信息密集、组织清晰的观感；并明确要求repo 分区放侧边、标签等筛选放顶部。本设计经可视化伴侣（浏览器线框/高保真 mockup）多轮确认。

推荐方案

选择性吸收：保留全部既有功能与信息流，只重排前端布局并升级卡片。三块改动：

1. 信息架构：repo 上侧边、标签上顶部

  • 左侧栏 = 仓库导航：全部 + 各 repo（色块头像 + 名称 + 数量徽章 + 可更新数提示）+「同步新源」。单选，驱动现有 viewState.repos。Saved Views 留在侧栏底部。
  • 顶部筛选 pill 行（新）：来源（全部 / Local / Git / skills.sh…）+ 彩色标签 pills +「更多▾」。Tag Groups 跟随标签迁到顶部「更多▾」。标签多时横向滚动 / 折叠。

2. 头部：双行紧凑

  • 行 1：标题 + 计数徽章 + 路径(次级) + 改位置 ｜ 检查更新(主 CTA，带 +N 角标) · 更新中心 · GitHub 导入 · ⋯(任务中心 / 平台管理 / 状态导入导出)。
  • 行 2：搜索(flex) + 排序 + 视图 ｜ 选择摘要「已选 N · 全选当前 · 清空」仅选中时内联出现。
  • 删除 CentralSelectionControls 常驻行：结果数并入头部计数徽章；批量动作仍走既有浮动 BulkActionBar。

3. 卡片：方案 C（信息分层型）

  • 左竖条编码状态（::before，仅"需关注"态上色，降低噪音）： 无 = 正常 · 琥珀 = 可更新 · 红 = 源缺失/需修复。 选中用蓝边 + 浅底（outline），与竖条互不冲突。
  • 行 1：名称 + 状态 chip（可更新/源缺失）+ 操作图标（安装 / 更新 / 删除）。
  • 行 2：描述（前置 AI 摘要 chip），行数随现有 comfortable/compact 档。
  • 行 3：彩色标签 + 卡上直接增删（hover 每个标签出 ×；点 + 内联输入/选择）。
  • footer 分隔线：左 = repo 色块 + repo 名 · preset · 近 30 天 N 次；右 = 平台点（已链接 N）+ 启用状态。
  • 自适应网格：repeat(auto-fill, minmax(~210px, 1fr))，窗口宽自动 2–4 列。

为何选这条路：本项目功能多于参考（更新中心 / facet / 批量 / AI 标签 / 任务中心），照搬参考的极简结构会挤压这些能力。选择性吸收在零数据流风险下拿到参考的"密集 + 清晰"观感，且复用已存在的 groupByRepository、SkillTag.color、密度档等基础设施。

备选方案

选项未采用原因
全面对齐参考密集风格（大改信息架构）需重排信息架构，且可能挤压本项目多出来的功能；风险高。
只重做卡片（不动排版）不解决头部 chrome 过重与 repo 分类缺位的问题。
卡片方案 A（参考密集型）信息量低于 C，丢失更新状态 / AI 摘要 / 已链接 N 等本项目特有信息。
卡片方案 B（平衡型）无状态竖条，"可更新/源缺失"的可见性弱。
repo 方案 R1（主区默认分区）纵向更长；改为"侧边导航 + 可选分区"更灵活。
repo 方案 R2（顶部 repo rail）与左侧 repo 导航职责重叠。
标签继续留在侧栏用户明确要求标签等筛选上移到顶部。
选「全部」时主区始终按 repo 分区纵向更长；默认平铺 + 可选分区开关更轻，仍保留分区能力。

数据与控制流（全部复用现有 store / viewState，不新增数据流）

  • repo 导航点击 → 写 viewState.repos（既有单选）→ filteredSkills。「全部」= 清空 repos。
  • 顶部标签 pill → 切换 viewState.tags（既有多选）；来源 pill → 复用既有来源筛选（查询 AST / facet 中的 source）。
  • 「全部」主区：默认 group="none" 平铺；「分组▾/按 repo」切到 group="repository"，走既有 groupByRepository() + CentralGroupedSkillList。
  • 卡上标签增删 → 调既有 tag store 的 assign/unassign（乐观更新）；事件需 stopPropagation 防触发卡片导航/选择。
  • 竖条 / 状态 chip ← 既有 updateStatus（CentralSkillUpdateState）+ inventoryFlags。
  • 平台点（已链接 N） ← 既有 platformIcons / togglePlatformLink。
  • 选择摘要 ← 既有 selectedSkillIds；批量动作仍走 BulkActionBar。

样式约定（沿用项目既有）

  • 卡片壳层延续 rounded-xl + ring-1 ring-border + bg-card + shadow-sm；footer 用 border-t border-border 分隔。
  • 主题：Catppuccin（Mocha/Frappe/Latte）+ accent 配色，标签哈希色取自 accent 色板，明暗自适应。
  • 竖条用 ::before 绝对定位（不占内容宽度）；选中态用 outline，两者叠加不冲突。

风险与对策

  • UnifiedSkillCard 多页面共用：footer / 竖条 / 可增删标签等为 central 场景新增，需通过 props 条件启用，确保 platform / project / marketplace / collection 场景视觉不回归。→ 新行为仅在传入对应 props 时渲染；保留现有 variant 分支与测试。
  • 顶部多一筛选行增加纵向高度：但删除了常驻选择行抵消；筛选行横向滚动 / 可折叠避免换行。
  • 内联标签编辑事件冒泡：误触卡片导航/选择。→ 复用参考的 stopPropagation 模式，输入框 onMouseDown preventDefault。
  • 自适应列下极窄卡片 footer 溢出/换行：→ 设最小列宽 ~210px；footer 元素优先级截断（repo 名 truncate，平台点不收缩）。
  • 竖条噪音：每张都有竖条会变花。→ 仅"可更新/源缺失"上色，正常态留白。
  • repo/标签从同一 facet 侧栏拆分：需保持 viewState 结构与 URL state / Saved Views 兼容。→ 仅重排 UI，viewState 字段（repos/tags/q/group/...）不变。
  • 遗留测试：项目已知 3 个遗留失败（Sidebar/Settings/PlatformIcon）。→ 不得新增失败；改动 Sidebar 时复核相关测试。

验收标准

  1. pnpm typecheck、pnpm build、pnpm lint 通过；pnpm test 不新增失败（除已知 3 个遗留）。
  2. 左侧栏仅显示仓库导航（全部 + 各 repo + 同步新源）+ 底部 Saved Views；标签与来源筛选出现在顶部 pill 行，Tag Groups 在顶部「更多▾」。
  3. 选「全部」→ 平铺；切「按 repo 分区」→ 区块视图（区头含 repo 名+数量）；选某 repo → 仅显示该 repo 技能。
  4. 卡片状态：可更新 → 琥珀竖条 + 可更新 chip；源缺失 → 红竖条 + 源缺失 chip；正常 → 无竖条；选中 → 蓝边 + 浅底。
  5. 卡片标签可 hover 删除、点 + 添加；颜色来自 tag.color 或哈希；点标签操作不触发卡片导航。
  6. footer 显示「repo 色块 + repo 名 · preset · 调用次数 ｜ 平台点（已链接 N）+ 启用状态」。
  7. 头部为双行；常驻"已选 0 · 共 N"行已移除；选择摘要仅在选中 >0 时出现在搜索行。
  8. 网格自适应：窗口变宽列数增加（2–4 列），窄窗 footer 不溢出。
  9. 其它共用 UnifiedSkillCard 的页面（platform/project/marketplace/collection）视觉无回归。
  10. 新增文案中英双语完整；明暗主题下标签/竖条/chip 对比度可读。
