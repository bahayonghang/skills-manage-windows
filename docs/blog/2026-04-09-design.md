# Desktop Design

> **Date:** 2026-04-09 · **Status:** historical · **Source:** `docs/desktop-design.md`

The desktop layout was designed around five primary surfaces, each answering a different question a user might bring to the app.

## The Five Surfaces

```text
┌──────────────────┬──────────────────────────────────────────────┐
│ Page             │ Question it answers                          │
├──────────────────┼──────────────────────────────────────────────┤
│ Central Skills   │ "What skills do I have?"                     │
│ Platform View    │ "What is installed in this agent?"           │
│ Skill Detail     │ "What does this skill actually do?"          │
│ Collections      │ "I want to manage a set of skills together." │
│ Discover         │ "Which SKILL.md files exist in my projects?" │
└──────────────────┴──────────────────────────────────────────────┘
```

The design starts from "Central is the source of truth" and treats every other surface as a view onto Central. That decision drove three downstream choices:

1. **Symlinks before copies.** A Central skill should propagate to platforms without duplication.
2. **Auto-centralize on import.** Anything entering SkillPort lands in Central first; per-platform installs come second.
3. **No surfaces edit a platform directory directly.** Edits go through Central.

## Page Mapping

| Page | Route | Layout |
| --- | --- | --- |
| Central Skills | `/central` | Two-column skill cards |
| Platform | `/platform/:agentId` | Two-column skill cards, scoped by agent |
| Skill Detail | `/skill/:skillId` | Markdown + sidebar with install state and collections |
| Collections | `/collections` | Selected card row above; member skills below |
| Discover | `/discover[/:projectPath]` | Project list + project skill detail |

## Why a Sidebar, Not Tabs

Five surfaces is too many for a horizontal tab strip on a 1280-wide window. The vertical sidebar collapses to icons under 960px and the command palette (`Ctrl+K`) is the keyboard accelerator.

## State Import / Export

The design pre-allocated a JSON shape for round-tripping the full state. The shape is documented in the [State Import / Export](../reference/state-import-export.md) reference; the design doc is its origin.
